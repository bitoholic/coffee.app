# Implementation Plan: Branding, App Icon & Settings Screen

**Branch**: `feature/012-branding-settings` | **Date**: 2026-07-24 | **Spec**: `specs/002-branding-settings/spec.md`

**Input**: Feature specification from `specs/002-branding-settings/spec.md`

## Summary

Apply the bitoholic brand identity to the coffee.app — custom colour scheme (`#C8102E` primary), logo mark in the top bar, gear icon navigation to a settings screen with a System/Light/Dark theme toggle that persists via Room.

## Technical Context

**Language/Version**: Kotlin 2.1.10, Compose Multiplatform 1.7.3

**Primary Dependencies**: Room KMP 2.7.1 (persistence), Material 3 (theme), Compose (UI)

**Storage**: Room (SQLite) — new `AppPreferences` table for theme preference

**Testing**: `./gradlew check` — JVM tests via Kotlin Test

**Target Platform**: Android API 26+ (primary), iOS 15+ (Compose Multiplatform)

**Project Type**: Mobile app (Compose Multiplatform)

**Performance Goals**: Theme switches instantly (<100ms), preference read on startup is async/non-blocking

**Constraints**: Must work in both light and dark modes. Theme toggle must be readable in both modes.

**Mobile Assumptions**: 
- Android adaptive icon (foreground + background layers)
- `BackHandler` for Android system back button on settings screen
- Preference stored locally in Room, single-row table
- Theme applies immediately via recomposition

**Scale/Scope**: 1 new screen (settings), 1 new entity (AppPreferences), colour scheme changes, top bar redesign, new app icon assets

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Focused Brewing Memory**: Branding reinforces app identity. Settings enable comfortable use in any lighting condition — directly supports the brewing memory use case.
- **Local-First Simplicity**: Theme preference stored locally in Room. No backend, accounts, or cloud sync.
- **Test-First Development**: Tests for preference save/load, theme state switching, and navigation.
- **User-Safe Data Changes**: Theme change is instant and non-destructive. No confirmations needed.
- **Beginner-Friendly Mobile Architecture**: Uses existing Room, Compose, and navigation patterns already established in the project.

## Implementation Order

1. **Theme.kt** — Brand colour constants and custom Material 3 colour schemes for light and dark modes
2. **App.kt** — Update to use custom colour schemes, add logo mark + gear icon in top bar, wire settings navigation
3. **AppPreferences.kt + AppPreferencesDao.kt** — Room entity and DAO for theme preference storage
4. **CoffeeDatabase.kt** — Register new entity and DAO
5. **SettingsViewModel.kt** — State management: read/write theme preference, expose current state
6. **SettingsScreen.kt** — Three-option radio/segmented control for System/Light/Dark
7. **App.kt (theme wiring)** — Use stored preference instead of `isSystemInDarkTheme()` only
8. **SettingsViewModelTest.kt** — Unit tests for preference save/load
9. **App icon assets** — Generate Android adaptive icon PNGs
10. **Update build.gradle.kts** — Ensure release signing config (already done)
